# Notion 문서 — 쓰는 법과 깨뜨리지 않는 법

Notion 페이지를 만들거나 고칠 때 이 순서를 따른다. 규칙은 전부 **실제로 겪은 실패**에서 나왔고,
계기 없는 규칙은 넣지 않는다.

## 1. 편집 절차 — 이 순서를 건너뛰지 않는다

1. **먼저 `fetch` 로 현재 내용을 읽는다.** 기억이나 추측으로 고치지 않는다.
2. **`old_str` 은 fetch 결과에서 그대로 복사한다.** 다시 타이핑하지 않는다.
3. **한 번에 한 곳만 고친다.** 여러 편집을 한 호출에 묶지 않는다.
4. **고친 뒤 다시 `fetch` 해서 눈으로 확인한다.** 응답이 성공이어도 반영을 확인한다.
5. 표·콜아웃 안의 텍스트까지 읽는다. 깨짐은 표 셀에서 자주 남는다.

### 왜 — 실측된 실패

| 겪은 일 | 원인 |
|---|---|
| `update_content` 가 "No matches found" 로 실패 | 렌더된 화면 텍스트로 `old_str` 을 지었다. **완전 일치가 필요하다** |
| 4개를 묶어 보냈더니 **1개만 반영**됐는데 응답은 성공 | 묶음 편집은 일부만 적용될 수 있다. 성공 응답을 반영 증거로 쓰지 않는다 |
| 한글 자모가 깨진 채로 몇 달간 남아 있었음 (`줘을`·`곹`·`지욱는지`) | 발행 후 다시 읽지 않았다 |
| 고치려던 글자를 **다른 글자로** 바꿔 넣음 (`곧` → `곰`) | 깨진 글자를 손으로 다시 입력했다. 원문 복사가 답이다 |

🔴 **문법을 추측하지 않는다.** Notion 자체 문법(콜아웃·표·색)의 정본은 MCP 가 제공하는
규격 문서(`notion://docs/enhanced-markdown-spec`)다. 필요하면 그걸 먼저 읽는다.

## 2. 계층 — 층마다 역할이 다르다

| 층 | 역할 | 담는 것 | 담지 않는 것 |
|---|---|---|---|
| **L1 허브** | 지도 | 인트로 콜아웃 1개 + 영역별 링크 | 진행 상황·설명·본문 |
| **L2 프로젝트** | 지도 + 현재 상태 | 목표 1줄, 상태 1줄, 자원 콜아웃, 하위 문서 링크 | 절차 상세·조사 과정·로그 |
| **L3 세부 문서** | 내용 | 규칙·범위·검증 방법·결과 | 다른 문서와 겹치는 재설명 |

- **L1·L2 는 본문을 쓰지 않는다.** 스크롤 없이 전체가 보여야 한다.
- L2 첫 화면에서 **"지금 어디까지 왔고 다음에 뭘 하면 되는지"** 가 읽혀야 한다.
- 하위 링크는 섹션(`##`)으로 묶고 한 줄 설명을 붙인다. 나열만 하지 않는다.

*계기: L2 에 결정 7행 표를 본문으로 넣었다가 걷어냈다. 중복을 없애려다 지도를 문서로 만들었다.*

## 3. 저장소가 있는 프로젝트라면 — Notion 은 현황판이다

**md 를 Notion 에 복사하지 않는다.** 저장소가 정본이고 Notion 은 가리킨다.

| Notion 에 두는 것 | 두지 않는 것 |
|---|---|
| 목표 1줄 · 상태 1줄 | 설계 상세 · 규칙 전문 · 스키마 |
| 자원 콜아웃 (저장소·문서 경로) | 결정 기록 — 저장소가 정본 |
| 하위 문서 링크 | 작업 로그 — 커밋 이력이 정본 |

갱신은 **마일스톤 때만.** 실시간 동기화하지 않는다.

*계기: 정책이 바뀔 때마다 md 와 Notion 을 둘 다 고치는 이중 작업이 됐다. 원인은 갱신 타이밍이
아니라 같은 내용을 두 곳에 둔 것이었다.*

## 4. 페이지 골격 (L3)

```
[아이콘: 이모지 1개]                  ← 제목 텍스트에는 이모지를 넣지 않는다
> 리드 한 줄 {color="gray"}           ← 이 문서가 뭔지 + 여기 없는 건 어디 있는지
## 📋 한눈에                          ← 표 1개 (3~7행)
---
## 1️⃣ 첫 섹션                        ← 최상위 섹션만 키캡 번호, ### 하위는 번호 없음
---
> 관련 문서 링크 한 줄 {color="gray"}  ← 푸터
```

## 5. 강조 — 상한을 넘기지 않는다

**강조가 많으면 강조가 없는 것과 같다.**

| 요소 | 한 페이지 상한 |
|---|---|
| 컬러 콜아웃 | 2개 |
| 빨강 강조 | 3개 |
| 굵게 | 문단당 1개 |
| 구분선 `---` | 최상위 섹션 경계에만 |

### 색의 의미는 고정한다

| 색 | 의미 |
|---|---|
| red | 하면 안 되는 것 · 데이터 손상 위험 |
| orange | 미결 · 나중에 터질 것 |
| green | 안전 · 완료 |
| blue | 정의 · 판정 기준 문구 · 용어 |
| gray | 부가 설명 · 근거 · 출처 (리드·푸터·계기 각주) |

콜아웃 배경은 셋뿐이다 — `blue_bg`(허브 인트로) · `gray_bg`(자원 묶음) · `red_bg`(진짜 위험).

## 6. 시그니처 — "계기" 각주

**규칙 뒤에는 그 규칙이 생긴 실제 사건을 회색 한 줄로 붙인다.**

```
- 거울 테스트 금지 — 구현을 그대로 베낀 단언은 통과해도 아무것도 증명하지 못한다

*계기: 실제로 사용했다가 지적받고 제거.* {color="gray"}
```

- 일반론은 규칙이 아니다. **여기서 실제로 나온 것만** 규칙이 된다.
- 계기가 없는 규칙은 규칙이 아니라 희망사항이다.
- 실패 사례를 지우지 않는다. "이렇게 하면 오판한다"가 다음 사람의 자산이다.

## 7. 글쓰기

| 위치 | 말투 |
|---|---|
| 리드 · 상태 줄 · 콜아웃 (사람에게 말 거는 부분) | 존댓말 |
| 본문 규칙 · 표 · 항목 (사실을 적는 부분) | 문서체 (`~다`, `~한다`) |

- **결론 먼저.** 근거는 아래로 내린다. 조사 과정은 지운다.
- 날짜는 절대 표기(`2026-07-24`). `어제`·`지난주` 금지.
- 상태는 날짜와 함께 적는다.
- 뭉갠 기록 금지. `4xx`·`차단됨` 대신 `401`·`404`. 뭉개면 판별 신호가 사라진다.
- 관측과 해석을 분리한다. 확인 안 된 원인은 **미확인 가설**이라고 명시한다.
- 표: 3항목 이상 나열되면 표를 의심한다. 열은 최대 3개, 셀은 한 줄.

## 8. 발행 전 체크리스트

- [ ] 아이콘을 설정했다 (제목에는 이모지 없음)
- [ ] 리드 한 줄에 "이 문서가 뭔지 + 없는 건 어디 있는지" 가 있다
- [ ] `📋 한눈에` 표가 있다 (L3)
- [ ] 강조 상한을 지켰다 (콜아웃 ≤2, 빨강 ≤3)
- [ ] 각 규칙에 `*계기:*` 각주가 있다 (규칙 문서인 경우)
- [ ] 날짜가 전부 절대 표기다
- [ ] 상위 페이지에서 이 페이지로 가는 링크가 실제로 걸려 있다
- [ ] 다른 문서와 중복이 없다 (있으면 링크로 대체)
- [ ] 🔴 **발행 후 다시 읽어 한글 깨짐을 확인했다 — 표 셀까지**

## 9. 안티패턴

- ❌ 부모 페이지에 본문을 쓰기 시작한다 → 지도가 문서가 되고 아무도 하위를 안 본다
- ❌ 하위 링크만 줄줄이 나열 → 뭘 눌러야 할지 모른다
- ❌ 모든 문장을 굵게/색으로 → 강조가 무의미해진다
- ❌ 같은 내용이 3개 문서에 복사됨 → 정본이 어디인지 모른다. **정본 1곳 + 나머지는 링크**
- ❌ 계기 없는 일반론 규칙 → 아무 행동도 바꾸지 못한다
- ❌ 진행 중인데 완료 표시를 미리 달아둠 → 상태를 못 믿게 된다
